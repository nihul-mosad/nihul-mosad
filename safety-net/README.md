# רשת ביטחון: סביבת ניסוי ובדיקות אוטומטיות

התיקייה הזו מאפשרת לבדוק כל שינוי במערכת **לפני** שהוא מגיע לצוות, בלי לגעת בנתוני המוסד.
הקובץ `../index.html` רק נקרא, ואף פעם לא משתנה.

## שלוש סביבות ניסוי

| קובץ (נבנה ל-`out/`) | מאיפה הנתונים | מתי משתמשים |
| --- | --- | --- |
| `staging-local.html` | מאגר מדומה בזיכרון הלשונית (`fake-firebase.js`), עם מוסד בדיקה פיקטיבי | הבדיקות האוטומטיות, ובדיקה ידנית מהירה |
| `staging-emulator.html` | Firebase Emulator במחשב (פרויקט `demo-nihul`) | בדיקה ידנית מול שרת Firebase אמיתי-מקומי, כולל חוקי האבטחה |
| `preview.html` | נתוני הדגמה קבועים (`demo-data.js`) | עבודת עיצוב, בלי כניסה |

## איך הנתונים האמיתיים מוגנים

1. **פרטי הייצור מוחלפים.** הבנייה נכשלת אם נשאר בקובץ שנבנה מפתח, מזהה פרויקט או כתובת של `nihul-mosad`.
2. **אין חיבור ל-Firebase של הענן.** בעותק המקומי סקריפטי Firebase הוסרו לגמרי. בעותק של האמולטור הם מוחלפים בעותק מקומי, שמחובר ל-`127.0.0.1` בלבד, ומזהה הפרויקט הוא `demo-nihul`. פרויקט שמתחיל ב-`demo-` לא קיים בענן.
3. **עצירה בזמן ריצה.** אם עותק ניסוי מגלה שהוא מחובר לפרויקט `nihul-mosad`, הוא מציג מסך אדום ונעצר. ההגנה הזו נבדקה.
4. **אין Service Worker.** כך עותק ניסוי לא נשמר במטמון של האתר האמיתי.
5. **פס אדום קבוע** בתחתית כל עותק ניסוי, כדי שאי אפשר יהיה להתבלבל.
6. **בדיקה אוטומטית** מוודאת שבזמן הבדיקות אין אף פנייה לשרתי Firebase.

## פקודות

```bash
cd safety-net
npm ci                      # התקנה, פעם אחת
npm test                    # בונה ומריץ את בדיקות המסכים והתהליכים (כ-15 שניות)
npm run test:diagnostics    # בדיקות אבחון לממצאים מהדוח (לא חוסמות)
npm run test:rules          # בדיקות לחוקי האבטחה. דורש Java, מפעיל את האמולטור לבד
npm run serve               # פותח את סביבות הניסוי בדפדפן: http://127.0.0.1:5050/staging-local.html
npm run emulator            # מפעיל את האמולטור. בחלון שני: npm run seed:emulator
```

כניסה לסביבת הניסוי: קוד מוסד `demo`. המשתמשים מוגדרים ב-`seed.mjs`: `admin` (מנהל), `morea` (מחנך כיתה א') ו-`math` (מורה מקצועי).

## מה נבדק

- **`tests/smoke.test.mjs`:** כל 17 המסכים אצל מנהל, המסכים המותרים אצל מורה מקצועי (ושהמסכים האסורים לא מופיעים לו), חמישה מסכים בנייד (בלי גלילה אופקית), וכרטיס תלמיד ותצוגות המשנה.
- **`tests/flows.test.mjs`:**
    - נוכחות: מחנך מסמן ושומר, הנתון מגיע לשרת, והמנהל רואה אותו גם בכרטיס התלמיד.
    - אירועים: מורה מקצועי מדווח בכיתה אחרת, המורה כותב רק אירועים, והאירוע מופיע אצל המנהל.
    - תמונת מצב: רמזור, ציון והערה נשמרים בשרת ומופיעים בכרטיס.
- **`tests/diagnostics.test.mjs`:** אבחון לממצא מ2 (מעבר תלמיד בין כיתות).
- **`tests/rules.test.mjs`:** 9 בדיקות לחוקי האבטחה. אורח, משתמש זר, מחנך ומורה מקצועי מקבלים בדיוק את מה שמותר להם.

## מגבלות

המאגר המדומה מחקה את Firebase, אבל הוא לא Firebase. בדיקות הממשק והתהליכים רצות עליו. בדיקות החוקים רצות על האמולטור האמיתי של Google, ב-GitHub Actions ובמחשב שיש בו Java.
